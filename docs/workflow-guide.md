# math model skill 七步工作流 · 2.0

这套技能按你的习惯组织：**读题 → 检索 → 共同讨论 → 实验设计 → 代码实验图表 → 成稿打磨 → 模拟质询**。你主导问题理解和关键模型选择，我提供有依据的研究、推导、执行与修订。编号用于调用，可以往返，不是七道审批或七份必交报告。

第5步只完成代码、实验、验证和图表；第6步才写论文正文。新的结构发现可随时返回第3步讨论或第4步设计小检查。已有成果时直接进入对应步骤，复用现有材料。

## 七个入口

| 步骤与调用名 | 实际工作 | 交给下一步的成果 |
|---|---|---|
| [1 · math-model-skill1-read](../skills/math-model-skill1-read/SKILL.md) | 保留原来的完整读题：题面、图表、附件说明、限定词、跨问关系与结构线索 | 逐问任务清单、来源与未明条件 |
| [2 · math-model-skill2-research](../skills/math-model-skill2-research/SKILL.md) | 查历史文献和原始资料，寻找合理模型、机理与算法，比较适用前提 | 少量真正可行的候选、可靠来源、取舍依据和待验问题 |
| [3 · math-model-skill3-debate](../skills/math-model-skill3-debate/SKILL.md) | 准确承接你的理解，讨论最影响路线的分歧，共同修正模型与方法 | 当前方案及“问题—观察—方法—主张—证据—边界”卡 |
| [4 · math-model-skill4-design](../skills/math-model-skill4-design/SKILL.md) | 按模型结构选择求解算法，按主张设计有判断力的实验 | 可执行的最小计算、评价指标、比较方式和补证安排 |
| [5 · math-model-skill5-execute](../skills/math-model-skill5-execute/SKILL.md) | 自主完成已定路线的代码、数据核查、实际求解、验证和图表 | 逐问真实结果、图表说明、证据边界与复现入口；不写正文 |
| [6 · math-model-skill6-refine](../skills/math-model-skill6-refine/SKILL.md) | 写作并反复打磨故事线、摘要、表达和图表，查技术漏洞 | 围绕中心发现的论文或修订稿、重要缺口与修改说明 |
| [7 · math-model-skill7-rebuttal](../skills/math-model-skill7-rebuttal/SKILL.md) | 模拟内部评阅和答辩，追问最关键漏洞，检查实际提交障碍 | 有位置和证据的质疑、诚实试答、最小补救任务 |

## 直接复制使用

```text
使用 $math-model-skill1-read，完整阅读题目与附件说明，
解释全题并生成逐问任务清单。这次只读题，不求解。
```

```text
使用 $math-model-skill2-research，检索适合本题的历史文献、模型与算法，
读关键原文，比较成立条件，给出值得我们讨论的方案。
```

```text
使用 $math-model-skill3-debate。我的理解是：……
请准确表达我的意思，找最强的支持和反对依据，和我一起修正，
明确模型、论文主张、贡献及需要什么证据。关键分歧先与我讨论。
```

```text
使用 $math-model-skill4-design。我们已经确定的模型是：……
请选择值得试用的求解算法，并围绕主张设计必要实验和判断标准。
这次只设计，不运行完整实验。
```

```text
使用 $math-model-skill5-execute，按我们已经确定的路线和实验设计，
完成代码、真实实验、验证和图表。先跑通关键路径，再完成授权范围。
本步不写论文正文。
```

```text
使用 $math-model-skill6-refine，依据实际结果成稿并反复打磨主线。
突出真正成立的结构发现，查技术漏洞，把评价融入论证，
不要把正文写成逐条回答评委。
```

```text
使用 $math-model-skill7-rebuttal，按原题和实际证据模拟内部评阅。
找最影响可信度的质疑，给出有依据的回答与最小补救。
这次只预审，不改模型或开展长计算。
```

也可以合并授权：“使用第4、5步，先设计，再实际完成代码、实验和图表。”已认可的路线无须再次确认；你明确说“只讨论”“只审摘要”“暂不做第三问”时，范围会保留。第3步如果还缺你的关键判断，会给一个聚焦的问题；不会把沉默当同意，也不会虚构你的观点。

## 非常规思路怎样进入工作流

首个可信解可以直接来自解析关系、消元、几何变换、分解或其他有依据的表示。无需先完成传统枚举或所有小问。每个值得投入的猜想先找一项能决定采用、收窄或转向的检查。

转化会说明自己是等价、可靠筛选、近似、受限策略还是启发式。一个推论被反例推翻，不必抛弃整条路线；保留成立的部分，调整主张和证据。常规算法同样可以使用，选择标准是它能否解决本题的困难，而不是名字是否新奇。

论文主张与证据卡例如：某项任务有什么瓶颈；我们观察到什么；因此采用什么模型或转化；它预计改变什么；需要哪条证明或哪项实验；什么结果会推翻主张。实验后把“预计”改成实际支持的结论，不预写提升百分比。

## 官方要求与评阅依据怎样影响技能

本次实际核读了官方章程、2026参赛规则、论文格式规范、2026 AI试行规定、当届通知及参赛须知，并查读全国评阅规范及部分公开A题专家讲评。具体版本、原始链接、阅读范围和应用方式见 [规则与评阅依据](../skills/math-model-skill1-read/references/rules-and-review.md)。

官方主要标准关注合理假设、建模创造性、正确结果与清楚表述；按题目形成具体评阅细则。没有普遍要求先做回归、K折、SHAP或达到5%的提升。新版按任务区别机理、数值、优化、预测等证据；敏感性分析可以发现脆弱处，不预设必须证明稳健。我们没有获得并熟读五届完整内部评分表，也不据公开案例虚构分值或获奖概率。

2026规则中与协作直接有关的要求已写入共享参考：赛中避免获取当届解题交流；核心建模与分析由队伍主导，AI参与内容需真实人工核验，并按当届规范披露。AI自检不会被记成人工审核。第7步是内部模拟质询，实际全国或赛区面试/答辩按当届安排，不套用顶会正式rebuttal流程。

正文、匿名、附录代码、文件大小、AI声明与提交期限在第6—7步按实际成品核对。今年数值与位置要求只是核验快照，换届时重新查。技能默认准备本地成果；正式上传仍须具体授权及实际平台操作证据。
