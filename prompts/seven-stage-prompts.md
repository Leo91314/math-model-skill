# 七步工作流配套提示词

适用于本项目当前安装的技能。方括号替换成实际内容；会话已经有题目、结果或稿件时直接引用，不用重复粘贴。每次选择当前阶段的一条即可，不要一次发送全部模板。

**搭配方式：一个Liminghao主技能，按实际缺口补充辅助技能。** 七步控制研究范围；BZD负责特定章节或模型的检查；科学计算技能负责实现；文档和绘图技能负责成品。下面是供你今后调用的提示词，本次只核对技能内容与组合，没有执行这些研究任务。

## 1. 完整读题

```text
使用 $math-model-skill1-read，完整阅读[题目及附件路径]。
PDF中的公式、图示和提取不清的内容，结合本地PDF技能回看原页。
解释研究对象、机制和各问任务，列清输入、单位、目标、硬约束、限定词、跨问关系及交付物，并保留来源位置。
区分明示事实、直接推论、待设假设和歧义；识别有依据的结构线索，但不提前定模型。
本次只读题，不求解。产出一份能供后续建模使用的逐问任务清单。
```

若题意特别绕、需要逐句核对，另用：

```text
结合 $math-model-skill1-read 与 $bzd-problem-translator，对照已提供的完整原题复核[具体段落或条件]。
重点查量词、单位、对象范围和问间继承，明确哪些是题面要求、哪些只是推断。
最终只补充改变理解的发现，不重复已有完整报告，不展开求解。
```

## 2. 检索可行模型与算法

```text
使用 $math-model-skill2-research，依据现有题意和数据条件检索可行方案。
实际查读历史文献、原始论文和官方技术文档，围绕本题困难寻找模型表示、机理关系与求解算法。
比较少量真正有竞争力的路线：解决什么、需要什么输入、成立条件、实现成本、主要风险，以及下一项最小验证。
若需要补充整题思路，可结合 $bzd-modeling-ideas；它的推荐作为讨论候选，不代替我的决定。
允许结构变换和非常规方法直接成为候选；仅见摘要的来源标明范围，不编造创新或效果。
交付来源、候选取舍和待讨论分歧；本次不运行完整实验。正式赛时遵守当届检索与交流限制。
```

已有具体模型名，想查它是否适配时：

```text
使用 $bzd-model-dictionary 核查[具体模型名]，再结合 $math-model-skill3-debate 讨论其适配性。
本次评估包括当前会话已给的题目、数据说明和候选方案，不重复索取材料。
说明模型的输入、假设、可识别性、限制、验证方法及与本题的关系；数据不足时给条件化判断。
只查询相关记录，保留字典来源和使用声明，不把字典条目当成已验证的解题方案。
```

## 3. 表达理解，共同修正模型

```text
使用 $math-model-skill3-debate。我的理解是：[自己的直觉、推导或方案]。
先准确表达我的意思，再给出最有力的支持、反例和替代解释，聚焦最影响路线的分歧。
需要精确推导时结合 $sympy，明确符号假设与定义域，并核对结果；不为所有数值问题强求闭式解。
共同明确变量、目标、约束、关键假设与方法，形成“问题瓶颈—核心观察—模型/转化—论文主张—所需证据—适用边界”。
区分等价、近似、受限策略和启发式。我的关键选择尚未确定时保留讨论；已经认可的决定不反复确认。
本次先讨论，不启动完整实验，不预写性能提升。
```

## 4. 设计实验并选择求解算法

```text
使用 $math-model-skill4-design。我们已经确定的模型和主张是：[内容，或引用已有讨论]。
根据变量类型、目标结构、约束、评价成本与精度需求，选择有依据的求解算法；按需读取相应科学计算技能。
把每项关键主张对应到最小必要证据：推导、特例、数值误差、完整可行性、样本外效果、优化质量或敏感性。
写清输入工况、指标与单位、参照、比较口径、判断标准和预计图表用途；未运行的内容明确标记。
无需为机理或几何题套回归、K折或SHAP。参数扰动范围有依据，敏感性分析不预设必须得到稳健结论。
先设计最小真实计算，再安排有判断力的扩展。本次只设计，不执行完整实验。
```

实际模型决定是否在末尾追加一个辅助技能，见后面的配对表；不必把全部库名字复制进去。

## 5. 完成代码、实验与图表

```text
使用 $math-model-skill5-execute，按已确定的模型和实验设计完成[指定问题或范围]。
复用现有代码、附件与依赖，用项目 .venv/bin/python 先跑通最小真实输入到最终指标和关键约束的链路，再完成本次范围。
按模型需要调用相应科学计算技能；失败先判断根因和路线，不无依据加模块、放宽约束或替换参数。
实施必要的对照与验证，保留实际输入、参数、运行命令、适用的随机种子和输出；区分真实运行、推导与未做检查。
基于真实结果制作并查看图表。需要论文级图形时使用 $nature-figure，后端明确选Python，版面服务中文数模论文。
交付代码、逐问结果、验证证据、图表说明与复现入口。本步不写论文正文。
```

遇到Excel原始附件或指定结果模板时追加：

```text
结合本地 spreadsheets 插件的 Spreadsheets 技能处理[Excel文件/结果模板]。
保留指定工作表、字段、单位、编号和布局，核对读入与导出后的关键数值；不要为套模板新增无关工作表。
数值模型继续使用项目解释器，表格产物按该技能要求处理。缺值和异常值先说明依据，不默认删除或插值。
```

## 6. 写正文，打磨故事线

```text
使用 $math-model-skill6-refine，依据[已验证结果和当前稿件]撰写或修改[指定章节/全文]，语言为中文。
先明确真正成立的中心发现，再组织“困难—观察—模型转化—求解—证据—结果解释”的叙述。
核对假设用途、关键推导、单位、约束、理论前提与数值一致性；发现实质漏洞时说明最小补证，不用措辞掩盖。
压缩通用算法介绍和重复内容；贡献与题目强绑定，保留适用范围。模型结果改变时同步检查摘要和图表。
本次授权你检查并修订稿件；仅在相关章节有实际缺口时调用对应BZD审查技能，审查发现直接用于修改。
保持正文主线，修改记录另列，不把文章写成逐项回答评委。
```

如需正式文件，在这条提示后选择追加一种格式：

```text
输出LaTeX源文件和编译后的PDF，结合 $latex-writing 与本地PDF技能。
采用已提供的当届模板；通用期刊样式不能覆盖比赛要求。实际编译并逐页检查最终PDF。
```

或：

```text
输出可编辑Word，结合本地 documents 插件的 documents 技能。
保留已提供的比赛模板和中文格式要求，实际渲染并逐页检查，交付最终DOCX。
```

## 7. 模拟评阅、质询与最小补救

```text
使用 $math-model-skill7-rebuttal，对照原题、当前稿件及实际证据，模拟内部评阅和答辩。
已有模型、求解、结果与验证章节时结合 $bzd-model-solution-checker，重点找会改变答案或削弱核心主张的缺陷。
每项重要质疑给出具体位置、证据、影响、当前能够作出的回答和最小补救；已被证据回答的事项关闭。
区分需要改模型、补实验和改表达的问题；不因缺少某种流行算法或检验就判定不足，不预测奖级或编评分权重。
本次只预审，不修改模型、不运行长计算、不对外发送。回复记录与正文分开，保留仍成立的中心发现。
```

需要按评审修复时，再发：

```text
按刚才的审查结论，用 $math-model-skill5-execute 补必要实验，再用 $math-model-skill6-refine 修订受影响的正文、摘要和图表。
执行已有授权范围的修复，不重跑无关工作；需要改变尚未定案的核心模型选择时，集中与我讨论。
主文按自身论证结构组织，另给简短的修改说明。
```

## 科学计算技能配对

把下表中适合的一句追加到第4或第5步即可。算法工具的适用性不等于本题已有数据或参数支持；不需要时不调用。

| 本题需要 | 辅助技能 | 可追加的话 |
|---|---|---|
| 精确方程、导数、恒等式或解析条件 | sympy | “结合 $sympy，明确表达式、符号假设与定义域，求解后代回核验。” |
| 约束优化、多目标与Pareto权衡 | pymoo | “结合 $pymoo，明确决策变量、目标、约束、预算及方案选择依据，最终回原问题复核可行性。” |
| 排队、资源争用、离散事件系统 | simpy | “结合 $simpy，先说明事件与资源机制、时间单位和输入来源，采用有上限的运行及适当的独立重复。” |
| 回归推断、参数解释、时间序列 | statsmodels | “结合 $statsmodels，按响应、观测单位和相关结构选模型，检查残差与估计限制，不把显著性当因果。” |
| 预测、分类、聚类或降维 | scikit-learn | “结合 $scikit-learn，明确样本单位与评价目标，训练内拟合预处理，划分尊重时间或组间依赖。” |
| 图、网络、路径与拓扑 | networkx | “结合 $networkx，依据原始数据定义节点、边、方向与权重，再实现题目需要的图计算。” |

一般ODE积分、数组计算或普通数值优化可直接用已有NumPy/SciPy，不必强行找一个技能名。连续微分方程与离散事件仿真不同，不能因为都叫“仿真”就套SimPy。优化器不能替代目标和约束的建模。

## 局部审查：有相应材料时再用

这些技能通常先诊断。希望它实际修稿时，提示词明确写“检查并修订”，并交给第6步整合；不需要每次全部执行。

| 你要处理什么 | 辅助技能 | 应有材料 |
|---|---|---|
| 问题重述是否偏题 | bzd-problem-restatement | 完整题面及重述；也可明确要求从题面生成重述 |
| 问题分析是否连接模型 | bzd-problem-analysis-checker | 原题和问题分析草稿 |
| 假设是否必要、失真或无用途 | bzd-model-assumption-checker | 原题、假设段落，相关模型内容可补充 |
| 符号与正文公式是否一致 | bzd-symbol-notation-checker | 符号表及相关正文，全文更便于查一致性 |
| 摘要是否独立可读 | bzd-abstract-checker | 摘要即可；没有正文时不声称已核对数值真实性 |
| 引文、附录、程序与包内容 | bzd-reference-appendix-checker | 稿件、引用和实际支撑材料，缺失项注明未核验 |

摘要专用：

```text
使用 $bzd-abstract-checker 检查这份摘要，再用 $math-model-skill6-refine 给出修订稿。
让读者独立看清问题、方法、结果和亮点，核对已提供正文中的数字与证据。
只给摘要时完成能够确定的文字审查，不索要全文作为开工条件，也不猜测未提供的实验。
不预设固定字数门槛，最终页数服从当届模板。
```

## 论文图与AI披露

精修一张图：

```text
使用 $nature-figure，后端选Python，根据[结果文件]制作/修改[指定图]。
图要支持的结论是：[一句话]。先核对数据能否支持，再选择必要图形与面板。
字号和尺寸以中文数模正文中的实际可读性为准，不机械套Nature期刊尺寸。
导出PDF和PNG，保留绘图脚本和数据来源供我核查；实际查看文字、单位、图例、裁切和遮挡。
误差带必须有真实含义，不为美观隐藏反例或更改数据。
```

整理正式披露：

```text
使用 $bzd-ai-usage-disclosure，根据现有真实对话、代码与结果记录，以及我补充的人工采纳/修改/核验情况，整理本届AI使用材料。
先核查当前官方要求；已有事实直接复用，真正缺失的历史信息向我集中核实，不从论文风格猜测。
信息充分时生成声明和AI工具使用详情.pdf，并检查匿名与材料一致性；缺失项只能留在明确标记的工作草稿中。
不要把AI自检写成人工审核，不生成虚假的未使用声明。本次仅在本地准备，不上传。
```

`nature-polishing`主要用于英文论文重构或翻译；只有明确需要英文稿时再调用，中文数模正文默认用第6步。`nature-data`面向特定期刊数据声明，竞赛提交不默认需要。

## 两句常用补充指令

出现错误或结果反常：

```text
使用 $math-model-skill5-execute，处理[运行命令、症状与预期]。
先用最小复现区分数据、模型、算法、实现和环境根因，修复后重跑受影响部分。
若证据否定路线就重新判断，不连续打补丁；不把程序退出成功当模型正确。
```

换任务继续：

```text
读取README、AGENTS和已有task_plan、findings、progress，核对当前文件与记录。
说明已验证成果、待决问题和下一步，再按七步中的相应技能继续已有授权工作。
第5步不写正文，第3步保留我尚未决定的关键选择；已通过且未受变更影响的工作不从头重做。
```

项目已有续接记录时直接复用；`planning-with-files`可用于确实需要持续计划的长任务，不必另建一套记录。`jupyter-notebook`用于你明确需要交互式笔记本时，普通求解脚本不必强制转Notebook。两个现有Hooks继续负责环境提示和语法检查，不负责证明模型正确。

完整七步职责见 [使用指南](../docs/workflow-guide.md)，技能测试范围见 [验证报告](../docs/historical-validation.md)。
