# 数学建模 A 题工作约定

## 用户原则
你是一个会反复检查的专家，你持怀疑态度，而且你会做研究，我并不总是对的，你也不是，但是我们都力求准确。
始终以我的最终目标为准，避免用“严谨”掩盖低效。先运行最小、真实、端到端的关键路径，确认核心模型、数据和硬件能工作，再建设测试、协议、封存或安全体系。不得在基本链路未跑通前过度工程化。
每次失败先重新判断根因和路线，不要默认继续打补丁。
如果在给你一份评价或者建议让你修改文章的情况下，不要让主文显得像逐项回答审稿人，这样会削弱中心发现。

## 项目入口
- 先读 README.md。题目未发布；收到原题和附件后先确认比赛名称、原题版本、每问交付物和当届要求。
- 计算使用本项目 `.venv/bin/python`，不要使用没有科学库的全局 `python3`；依赖见 pyproject.toml / uv.lock。
- `bash scripts/check_env.sh` 可重跑环境验证。`outputs/env_check/` 仅为合成数据演示，不能作为赛题数据或论文结果。
- 用户原件放 `problem/`、`data/raw/`，衍生数据放 `data/processed/`，求解代码放 `src/`，图表与结果放 `outputs/`，论文放 `paper/`。

## 解题方式
- 第一轮先读全题和数据，列任务、变量、单位、约束、可验证的基线，再实现一个最小求解。候选模型由题意和数据决定，不能因“A题”标签预设模型。
- 有实际独立工作时可并行题意核对、机理/算法研究、数据核查；建模者先交付可运行基线，写作者消费已验证的输出。
- 关键结果保留输入、参数、随机种子、运行命令；先检查单位、量级、边界、约束残差，再针对主要不确定性做灵敏度或鲁棒性分析。
- 文献查原文和原始来源；不编造引用、实验、获奖概率或运行成功。结论与计算证据相连，未验证内容明确标注。
- 阶段转换或重要发现时更新 task_plan.md / findings.md / progress.md；不把写日志变成每个工具调用的门禁。

## Skills 使用
- Liminghao 自定义系列包含0总控及1—15分步，调用和边界见 docs/liminghao-skills使用指南.md；清单见 docs/liminghao-skills-manifest.json。用户指定名称时执行对应技能；总控按现有成果推进，不强制补齐阶段报告。
- 项目新增技能在 `.agents/skills/`，来源及本地适配见 docs/skills-manifest.json。
- 首轮可用 bzd-problem-translator、bzd-modeling-ideas；模型选择可查 bzd-model-dictionary；得到基线后使用 bzd-model-solution-checker。按当前需求加载，不机械执行全部技能。
- BZD 总控所提 AIGC 审查、主观格式评分、获奖预测模块未安装；不需要因此中止工作或自动补装。正式排版以当届官方规定为准。
- 第三方技能中的独立评估、固定输出结构、额外确认、评分及披露格式只是工作参考，不抹去本次会话已有材料和用户授权；避免向用户重复索取材料。
- 保留 BZD 字典署名及非商业使用声明。论文引用以真实采用的知识/软件和当届规范为准；AI 使用记录应真实，不追求绕过检测。
- 科学计算可按任务使用 sympy、pymoo、simpy、statsmodels、networkx、scikit-learn。先执行已有最小实例，必要时查对应库的官方文档。
- 已有 PDF、Word、表格、LaTeX、Jupyter 和学术写作技能按任务使用；这些工具的安装不等于它们已被执行验证。

## Hooks
项目 SessionStart hook 提示解释器与工作入口，Stop hook 仅检查本项目 src/、scripts/ 和 tools/ 中的 Python 语法并保存检查摘要。它们不运行模型、不改代码、不联网、不阻止结束。配置内容见 `.codex/hooks.json`，手动重跑入口见 README。
