# 建立基础模型：得到能直接实现和检验的数学描述

围绕题目所求建立足够简单的核心模型，供真实基线运行和后续扩展。首次使用本系列且尚未读过时，阅读[共同原则](../liminghao-skill0-workflow/references/principles.md)。复用现有读题、转化、数据与调研成果，不要求用户先跑完其它技能。

## 最小输入与边界

需要当前问的完整任务、关键条件，以及已知输入或数据结构。材料不足时先构造确有依据的部分，保留未知量及其来源缺口；不得假造数值、偷偷增加题目没有的约束，或依据往届题目预设模型。用户已指定模型时先判断其适配性，有实质冲突应解释并提出最小可行替代。

本技能完成的是可实现的数学模型。没有实际求解就不能写“结果表明”“收敛良好”或给出假想论文结果。

## 建模动作

1. **固定计算对象与边界。** 明确系统包含哪些对象、时间与空间范围、参考坐标和正方向，哪些外部作用作为输入。区分状态量、观测量、待估参数与可控制变量，不能把不可控条件当优化变量。
2. **选择最小必要机制。** 从题目目标倒推必须描述的关系，可为守恒/平衡、几何、概率、统计或离散规则。只有会改变所求指标的机制才进入首个模型；不为显得高级加入没有数据支撑的参数。多个合理候选先以解释性、输入可得性、计算成本和可检验性比较。
3. **逐条建立必要假设。** 对真正使用的假设说明简化对象、依据、进入哪条方程及主要失效情境。题设事实直接标作事实，不能包装成假设；“忽略所有误差”“模型一定准确”不能作为论证。对精度影响未知的近似，列为待检查问题。
4. **推导核心关系。** 写明符号和单位、方程或规则的来源、初始/边界条件及分段条件。关键步骤让读者能追溯，常规代数适度压缩。运动、能量、面积等相关量应使用同一状态定义和坐标约定，交界处说明连接方式。
5. **把题目指标落实到计算。** 明确平均量的区间与权重、极值的定义域、累计量的积分/求和口径、离散近似如何产生。优化模型给出变量范围、目标和全部题设约束，约束适用“全过程”时不能只写终点。多目标题优先保持题设偏好；自定权重须说明依据。
6. **检查是否可求解。** 核对方程与未知量、参数是否可辨识、所需数据是否存在，讨论必要的尺度和量纲一致性。方程数量相等并不保证解唯一；约束冲突、参数共线或只观察组合量时应指出。先修正结构问题，再考虑求解器。
7. **给出最短实现路线。** 确定输入到输出的计算顺序、一个真实简单工况及一项有区分力的检查。需要数值库时按问题选现有工具；仅在能减少推导错误时使用符号工具，不强制装库或设计通用框架。

## 输出与完成条件

默认必要报告写入 `outputs/workflow/06-model.md`，短推导可直接回复。输出包括模型目的、输入与符号、必要假设、核心方程/目标/约束、求解顺序、未定参数和验证入口；组织成论文可用的连贯论证，避免把正文写成逐项答审稿意见。

完成意味着：另一位实现者凭这些定义和现有输入能写出最小求解，不必猜单位、条件、目标口径或关键公式。可解性尚不确定时明确该状态，不能以公式数量替代完成依据。

## 失败分流与阶段接口

数据不足先判断是否可用已知关系推导、可合理降维或需要补充观测；机理不确定转向定向调研；数学不可辨识则固定有依据的参数或缩小主张范围。不要反复增加自由参数补偿结构缺陷。

向 `liminghao-skill7-baseline` 交付最小输入、方程、计算顺序和预期输出；向 `liminghao-skill8-check` 交付单位关系、边界、约束与解析特例。后问扩展保留前问可处理的特例与候选方案，实际运行仍使用项目 `.venv/bin/python`。
