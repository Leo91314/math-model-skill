# 基础验证：判断基线能否支持下一步

优先找出会推翻当前答案的明显错误，让基础模型和程序值得继续投入。首次使用本系列且尚未读过时，阅读[共同原则](../liminghao-skill0-workflow/references/principles.md)。本阶段是对真实基线的针对性核查；完整数值收敛、敏感性和稳健性分析交由 `liminghao-skill11-validate` 按需开展。

## 最小输入与覆盖范围

需要任务定义、关键公式、实际结果及对应输入；有代码或命令时直接读取并运行最小检查。先复用基线已有检查，不因阶段切换机械重跑。用户只给论文或结果截图时可做静态逻辑核对，但明确无法验证实现与运行记录。没有真实结果时不声称完成数值验证，也不把合成特例替代真实基线。

涉及计算使用项目 `.venv/bin/python`。允许写有独立判断力的小检查脚本，不构建大测试平台，不写只重复原公式、没有可能暴露错误的测试。

## 选择有区分力的检查

1. **确认检查对象。** 对齐题目要求、代码所算量和论文所述量；核对结果所用输入、参数、初始条件与运行版本。若表格来自旧运行，先解决对应关系，不能混用结果继续比较。
2. **查单位与量级。** 从输入经关键公式到输出追踪量纲，检查角度/弧度、速度/位移、功率/能量、平均/累计等易混口径。用有依据的粗略上下界或数量级估计比较；“看起来合理”不是证据。不能靠改单位标签修复实际计算错误。
3. **查边界与约束。** 核对初值、终值、连接点、符号方向及最容易违约的位置。将约束代入结果计算实际残差，报告最坏位置/对象。绝对误差阈值应结合单位、尺度和题目精度；只看求解器默认容差不够。若约束要求全过程，稀疏采样只能说明已采样点，出现风险即补查相应区间。
4. **选一个独立参照。** 根据模型使用手算、解析特例、守恒量、对称性、单调性、已知退化情形或另一计算表示。参照应与主程序有不同出错路径；把相同错误公式复制一遍的吻合不构成独立验证。特例脱离模型适用条件时不得强行采用。
5. **查方法是否实际完成。** 数值求解关注残差、收敛状态和无效值；优化关注约束满足及简单可行候选比较，随机搜索找到一个解不代表全局最优。统计模型优先查样本与目标定义、明显信息泄漏和评价集是否独立，不在这里自动展开完整统计诊断。
6. **解释失败并修复最小原因。** 对每个实质问题给出输入或代码位置、观测与预期、影响及根因判断。已有授权的局部修复可直接实施并重跑受影响的最小检查；用户仅要求审查时提供可执行修改建议。模型结构不合理则返回推导，不连续调参掩盖错误。

## 输出与完成条件

默认必要报告写入 `outputs/workflow/08-check.md`；短问题可直接回复。突出最关键结论，随后列检查对象、方法、实际值或残差、判定依据和覆盖范围。结论可为“可继续使用”“需先修复”“现有材料不足以判断”，不要虚构统一分数或获奖概率。

完成意味着：已经运行或阅读足以支持判断的证据，致命问题已修复或明确阻断，剩余不确定性有下一步去向。只运行了一个工况或检查了部分记录，应明确范围；基础核查通过不等同于物理模型已被实测验证。

## 根因分流与阶段接口

- 数据/语义问题：返回 `liminghao-skill3-data` 或读题阶段，保留出错记录。
- 单位、公式、边界或不可辨识问题：返回 `liminghao-skill6-model`，更新数学定义后再运行。
- 实现、精度设置、求解状态问题：返回 `liminghao-skill7-baseline`，重跑受影响指标。
- 只有高精度或扰动下可靠性未定：将关键指标、可疑机制和最低必要实验传给 `liminghao-skill11-validate`。

交付下一阶段时同时给出可以信任的部分和仍未检验的主张。若发现基本链路不成立，应暂停依赖该结果的优化与论文结论，但继续不受影响的独立工作。
