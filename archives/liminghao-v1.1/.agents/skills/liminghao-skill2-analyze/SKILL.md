# 分析与数学转化

使自然语言任务变成可建立模型的数学问题，支撑同一条论文主线。首次使用本系列时读 [共同约定](../liminghao-skill0-workflow/references/principles.md)。复用现有读题结论，直接回查关键原文；没有01报告不构成阻碍。

## 先明确数学对象
从题目和数据确定对象、索引集合、时间/空间尺度、坐标/参考系。区分已知参数、待估参数、状态变量和可自由选择的决策量：一个数值是否未知，不等于它可以优化；随时间变化的状态也不等于每时刻均可独立选择。

按各问实际需求识别任务：描述/正向计算、参数识别、预测、比较评价、优化设计、事件定位或解释机制。说明分类依据及所需输出，不凭题号或字母套模型家族。

## 转化动作
1. 将“效果”“代价”“尽量”“满足要求”等词落实到可计算量，定义单位、统计/积分范围、分母和汇总顺序。多个目标明确主次或保留真实权衡，不无依据加权。
2. 将限制按原题写成等式、不等式、逻辑或过程约束。区分硬约束、偏好、题设忽略项和自己拟加的假设；不能把困难的硬约束换成惩罚项后宣布可行。
3. 处理量词与依赖：全体、全过程、平均与某时点的条件分别约束什么。区分有限采样要求与连续范围要求，不以采样通过代替所有情形。
4. 把机制转为关系草图：对象之间的作用、信息如何传递、状态怎样产生最终指标。需要精确推导的关系留给model技能，当前先识别缺少哪一个关系、需要什么数据。
5. 给各问建立接口：前问传递公式、参数、状态、布局、评价函数还是可行候选；列出后问更换的工况。判断是否形成嵌套可行域、是否存在反馈或互相依赖，不能仅按题号画单向链。
6. 判断数据能否识别所需量。有多个未知量却缺独立约束时，指出可辨识性问题；预测问题区分训练/验证与未来可用信息，防止用结果反推输入；机理题没有实测数据时，不规划无法完成的“实际精度验证”。
7. 为各问提出最便宜的合理性检查：可手算特例、单位、极限、守恒、对称、约束或前问基线关系。此处设计检查，不假称已执行。

## 输出
复杂赛题默认 outputs/workflow/02-analyze.md，也可按用户范围直接回答。交付：
- 全题数学主线：对象、关系、评价与决策如何连接。
- 每问的数学任务卡：已知量/来源、状态或待估量、决策量、目标定义、约束及作用范围、输出和继承关系。
- 真正影响路线的口径选择、待论证假设和缺失信息，说明替代读法的后果。
- 可进入基础建模的关系，以及最小求解/验证入口。

符号表仅收录接下来实际使用的核心量，不铺设未使用符号。分类和关系描述需达到可实施程度，“用优化算法”“做数据分析”不能替代数学定义。

## 验收与下一步
检查每个决策变量是否可控、每个指标是否定义、每条硬约束是否保留、每个结果是否回答原题。直接后果和作者选择分开；缺参数仍可交付条件化结构。

若基本对象都无法确定，回到read定位歧义；若数据不支持待估量，转data/research或简化参数化；若只缺精确关系，交给model。模型建议必须能利用现有输入产生所需输出，不机械枚举多个无用模型。
