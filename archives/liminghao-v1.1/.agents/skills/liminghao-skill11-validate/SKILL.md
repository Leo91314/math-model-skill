# 结论验证：使证据强度与论文表述相匹配

## 输入与边界

消费用户指定结论、原题相关要求、模型和假设、代码、结果及已有检验。目标是确认哪些主张可保留、需要降级或必须重新求解。用户只请求审查时先审查现有材料；需要补算且在任务授权内时运行最有判别力的检查。无需重走前序阶段或生成全套检验章节。首次使用本套技能时读取 [共同原则](../liminghao-skill0-workflow/references/principles.md)。

材料不足时明确“证据不足”与“结果错误”的区别，继续可做的单位、逻辑和可行性核查，只追问真正关键缺口。使用真实题目输入；合成算例可以检查算法性质，但标明其身份，不能充当赛题结果或现实预测精度。

## 执行动作

1. **列出需要支持的具体主张。** 从“准确、可行、较优、稳定、解释了某机制”等表述中提取可检查命题，逐项对应已有证据、最可能失效处和最有判别力的下一项检查。优先验证会改变答案或推荐方案的问题。
2. **区分证据层次。** 模型有效性检查关注机制、假设和现实或题设是否匹配；数值检查关注程序是否准确求解所列公式。解析特例、独立实现和残差可相互补充，但两种算法接近只能支持相应计算的一致性，不能自动证明共同的物理假设正确。
3. **验证完整可行性。** 检查全部规定对象、全过程、交界和边界条件。离散时间点均通过不等于点间通过；必要时用事件定位、几何界限或临界区间加密确认遗漏风险。给出关键约束最大违反量、最小安全余量或相应证据，而不只引用求解器状态。
4. **检查数值误差。** 对影响结论的步长、网格、积分精度、容差或采样密度做有针对性的收敛比较。关注最终指标及临界事件是否稳定，避免只检查中间状态。用变化量解释报告位数；有系统误差或奇异行为时，加密未必能修复模型或算法缺陷。
5. **检查主要不确定性。** 从测量误差、参数来源、估计区间或题意选择扰动对象与范围，避免机械采用全部参数±10%。敏感性描述变化方向与幅度；稳健性判断方案在合理扰动下是否仍可行、有优势。区分“固定方案接受扰动”与“每个情形重新优化”，后者不能证明原方案可直接实施。
6. **核对最优性与推广范围。** 检查边界解、可行基线、有效界限或必要的独立搜索；多次算法结果一致仍不等于全局证明。同目标且可行域扩大时复评原候选，防止搜索退步被写成最优。没有实测数据时，结论限于题设与假设下的自洽性及数值可信度；有预测数据时按独立验证设计评估，避免用拟合样本代替外部证据。
7. **按证据更新结论。** 将结果分为支持、需限定、待补证或被反例推翻。反例推翻时回到对应模型或求解环节；补证后只重算受影响内容，不机械重复全部实验。论文正文按研究逻辑呈现关键证据，不写成逐条答复检查意见。

## 输出与完成条件

默认报告 `outputs/workflow/11-validate.md`，指定目录或隔离目录优先，简单检查可直接回答。实际补算用项目 `.venv/bin/python`；代码放 `src/`，验证数据与图表放 `outputs/`，记录输入、参数、命令及种子。

报告按需要包含“主张—检查方法—实际结果—证据含义—剩余限制”，并列出会影响结论的问题及最小修正。未运行的检查写为计划，不生成虚构误差、显著性、稳健性或获奖概率。

完成意味着本次指定的主要主张都有明确可信度判断，发现的致命问题已修复，或清楚交付其阻断状态和受影响范围。审查完成不等于模型通过；仍缺关键证据时明确不能作出的结论。已有证据足够后停止补测，不为章节数量追加无关检验。
