# 递进求解：让全部问题得到一致、可核查的回答

## 目标与输入

消费当前题面版本、逐问交付要求、真实数据、已有模型、代码及已验证结果，推进用户指定范围的完整答案。用户只指定某问时，就以该问为范围；不强制重读已有结论、不补齐前八份报告。首次使用本套技能时读取 [共同原则](../liminghao-skill0-workflow/references/principles.md)。

先定位已有程序入口，核对其输入版本、参数和最近一次实际运行结果。不能把旧工况结果、演示数据或未执行代码当作本次答案。材料缺失时继续推导、读取和求解不依赖缺失项的部分，仅追问确实阻断结论的关键输入。

## 执行动作

1. **明确求解依赖。** 用简表列出本次各问的输入、共享模型、新增条件、所需输出及当前状态。区分前问的数值输出、可复用的计算方法和仅在前问成立的假设。由题意选择模型，不按“A题”标签预设机理。
2. **确认基础评价可用。** 对一个已有可行输入检查状态量、最终指标和主要约束是否能实际算出。已有可靠基线直接复用；若基本链路尚未跑通，只补必要的最小求解与快速检查，暂不组织大规模搜索。
3. **逐问扩展。** 尽量复用已验证的状态方程、评价函数和几何关系，每问显式绑定对应参数、初始条件、边界和时间范围。参数表或附件变化时重新加载；禁止因共用函数而静默沿用前问常数。每次扩展先求一个简单候选，再覆盖要求的全部对象与工况。
4. **保留可比较的前问方案。** 若后问的可行域确实包含前问且目标、单位、评价口径相同，将前问可行方案直接带入复评。最大化问题的真实最优值不应因放宽约束而降低；若新搜索结果更差，保留较好可行方案，检查搜索、参数化或评价变化。目标不同或可行域不嵌套时不套用此关系。
5. **推进各问交付并利用新发现。** 为每问给出明确答案、适用条件、单位和所需结果文件。若新结构有望改变表示、减少后续计算或解释多问，可即时进入 `liminghao-skill10-improve` 做最小辨别检验，再返回求解，无需等待全题覆盖。卡住某问时说明根因并继续独立部分；没有可行解时如实报告，不用违反约束的高指标占位。
6. **核查连接与交付。** 检查上游输出到下游输入的量纲、索引、时间基准、坐标系及精度；确认摘要式结果表与实际导出文件一致。结构或评价发生变化时同步更新受影响结果。根据具体瓶颈与剩余交付决定是否继续改进，不为形式完整自动追加优化。

## 输出与完成条件

默认将简明求解记录保存为 `outputs/workflow/09-solve.md`；用户指定目录或隔离评估目录优先，短问答可直接回答。真实求解代码放 `src/`，数据和图表放相应 `outputs/` 子目录，使用项目 `.venv/bin/python`。

记录应包含逐问结论、共享与新增模型、关键参数、运行命令、输入与输出路径、实际运行状态及未解决限制；随机算法记录种子。按内容需要组织，不重复粘贴整篇推导。

完成意味着用户指定的各问均有可核查的回答或明确有证据的不可行性结论，关键连接和约束得到检查。因缺材料、运行失败或尚未求解而没有答案，属于部分完成；说明剩余工作，不能标为全题完成。仅有搜索结果时称为“当前较优可行解”，更强最优性表述需要额外依据。

## 失败分流

- 输入或跨问参数错配：返回数据核查与问题转化，修正后重算受影响结果。
- 方程、假设或任务口径不符：返回基础建模，不靠调整算法掩盖。
- 数值不收敛：先检查尺度、初值、约束可行性及求解条件，再选择适合的数值方法。
- 结果有效但性能不足：保留基线，转入针对瓶颈的改进。
- 结论依赖尚未检查的全过程、近似或不确定参数：标明待验证，并在需要时进入 `liminghao-skill11-validate`。
