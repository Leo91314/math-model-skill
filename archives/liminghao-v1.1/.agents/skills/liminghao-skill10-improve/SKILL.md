# 结构探索与模型改进

## 目标与输入

从题目目标和约束、结构猜想、已有观察或计算结果出发，寻找更合适的问题表示和求解路线，或改善现有方案。已有基线可作为参照；尚无基线也可以直接检验解析、几何、消元或分解思路，不必先完成传统求解或全题覆盖。首次使用本套技能时读取 [共同原则](../liminghao-skill0-workflow/references/principles.md)。

尊重指定问题、方法、算力及时间范围，不擅自扩展到全题或重做前序报告。用户只要思路时给出方案与待验证判断；已授权探索或求解时实际执行关键检验。材料不足先做可独立完成的推导或分析，仅询问关键缺失项。不凭“A题”标签选模型，也不将单篇获奖论文的路线当作通用模板。

## 执行动作

1. **提出可判定的问题。** 明确是寻找等价表示、解释计算现象、修复偏差、扩大方案范围，还是提高精度、目标值或效率。连接“已有线索—结构猜想—若成立会改变什么”，优先关注决定后续计算或解释的连接，而非先选高级算法。
2. **用最小证据判断方向。** 找一个关键推导、小实例、边界情形或局部对照，优先检验最可能失效的前提。观察、猜想、推导和计算可交替进行；失败先重判根因与路线，不默认补模块。检验服务于保留、收窄或转向，不要求预先建设全套测试，也不固定候选数量或探索时长。
3. **为新方法确定恰当身份。** 按共同原则判断它是等价改写、可靠筛选、数值近似、受限策略还是启发式。证明未成不自动放弃，也不以少数算例吻合冒充证明；明确缩小适用范围或改变身份后还保留什么价值。使用定理或算法保证时核对目标、约束和前提，不能只因函数具有某性质就迁移整套保证。
4. **按任务接到真实求解。** 需要形成数值方案时，将值得保留的路线以最小真实输入实现核心链路，明确变量转换、输出还原和约束检查；首个可信参照可以就是非常规方法。仅研究结构性质时交付对应推导与检验，不强制扩展为数值求解。未运行的推导不能写成已计算结果，合成小例仅证明该例行为。已有模型时保留原可行候选，便于比较或回退。
5. **在可信评价上搜索和复核。** 搜索前检查目标与关键约束计算。近似模型、代理模型或粗网格可用来筛选，最终候选需在足以支撑结论的原问题评价中复核；无法复核的部分说明限制。评价口径变化时重评参照，搜索器“成功”不等于实际可行。
6. **只对真实收益作同口径比较。** 宣称数值或效率改善时，使用相同输入、单位、工况、指标与约束口径，给出相应预算或停止准则；仅比较方案效果，不把额外算力写成算法优势。结合评价误差、随机波动和实现成本判断收益，仅补与主张有关的对照。差异不足以分辨时如实说明；约束违反不计作改善，多目标明确权衡。
7. **选择路线并界定结论。** 依据正确性、实现成本、解释力、后问复用和实测效果决定采用、继续检验或放弃。相同目标下可行域扩展应保留原可行解；多次搜索最好值称当前较优可行解，只有适用的证明、完整穷举或有效界限才支撑全局最优性。结构价值与数值优势分开表达，不因尚无性能比较否认已证实的等价简化。

## 输出与完成条件

默认写入 `outputs/workflow/10-improve.md`，用户目录或隔离目录优先，短回答可不落文件。使用项目 `.venv/bin/python`；实际计算代码放 `src/`，比较数据、候选参数和图表放 `outputs/`。

输出围绕本次判断：观察或瓶颈、结构猜想或改动、实际检验与结果、方法身份、采用决定及证据范围。宣称数值改善时附同口径比较与可行性依据；实际计算保留关键输入、参数、命令、随机种子和结果路径。仅提出方案而未运行时标为建议，不称已验证改进。

完成条件按用户任务判断：探索任务应给出有依据的路线决定或准确的待解前提；改进任务应说明收益是否成立及采用哪一方案。“反例成立、改作受限策略”或“未证明改善、保留原解”也是有效研究结果。用户要求的指标尚未达到时，报告差距和可行下一步，不宣称完成目标。

## 失败分流

结果变差先判断是目标口径变化、模型不适用、数值误差、搜索不足还是实施错误。修正评价回到基础检查；修改物理假设回到建模；大范围仍不可行时检查约束与输入一致性。若继续搜索的收益缺少依据，停止追加复杂度，转向能区分原因的检查或说明限制。
