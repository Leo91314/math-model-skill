# Liminghao 数学建模 Skills 使用指南

这套技能服务于一个目标：把准确的题意理解、可运行的模型、可靠的证据和清晰的论文连接起来。共 **15 个分步技能和 1 个总控技能**，安装在本项目 `.agents/skills/` 中。各步骤可以单独调用，也可以由总控按现有成果连续推进。

**1.1 版调整：** 结构发现从读题阶段开始；有依据的非常规表示可以直接成为基线；探索、计算和写作允许往返。已调整第0、1、5、7、9、10、13步及共同原则，调用名称保持不变。

## 直接这样调用

在本项目的 Codex 任务里发送下面这样的消息即可。普通文字写完整技能名也能表达调用意图；加 `$` 可以明确指定技能。

```text
使用 $liminghao-skill1-read，完整阅读我提供的题目和附件说明，
解释整题，并生成逐问任务清单。这次只读题，不求解。
```

```text
使用 $liminghao-skill0-workflow，根据当前文件和已有进度，
从读题推进到第一版可运行基线。先跑通最关键的一问。
```

```text
使用 $liminghao-skill5-plan，寻找有依据的结构突破口，
比较值得投入的路线，给出下一项最小验证。这次只规划，不计算。
```

```text
使用 $liminghao-skill10-improve，我还没有常规基线，
先检验这个结构猜想，实际做必要的小检查，判断采用、收窄还是转向。
```

```text
使用 $liminghao-skill8-check，检查刚才运行的基线，
重点核对单位、初始条件、约束和结果量级；发现错误就修复并重跑受影响部分。
```

```text
使用 $liminghao-skill11-validate，检查当前结论有哪些证据，
补做最影响可信度的验证，并说明哪些说法需要收窄。
```

```text
使用 $liminghao-skill13-write，依据已经验证的结果修改正文，
把这份评价转化为论证和表达上的改进，保持文章围绕中心发现展开。
```

不用重复上传本次会话已经提供的材料。若文件不在常用目录，给出路径即可。想限制范围时直接说明“只做第一问”“只审摘要”“先不运行长计算”或指定成果目录。

## 读题技能具体增加了什么

`liminghao-skill1-read` 在“理解背景、条件、各问任务”的基础上增加了以下实际动作：

1. **核对材料范围。** 确认年份、题号、版本和已有文件；正文、所有子任务、图注、表头、脚注及补充说明均在阅读范围内。PDF 公式或图示提取不清时回看原页。
2. **区分五类信息。** 分开标记题目明示事实、直接推论、待设假设、歧义/冲突及交付要求，并保留页码或段落定位。
3. **检查限定词和口径。** 除单位、时空范围、初始与边界条件，还核对坐标方向、参考点、索引、端点是否包含、平均分母、极值范围以及“所有”“全过程”“允许不同”等条件。
4. **拆开一问中的多个任务。** 同时要求“设计方案、解释可行性、输出数据”时分别记录，不只保留最后一个数值目标。
5. **明确跨问继承和变化。** 分清前问结果是否必要、参数是否已换工况，避免把输出时间窗误当全过程约束，也避免把本可独立的问题强行串行。
6. **把附件对应到交付。** 区分输入数据、参数表和输出模板；写清文件服务哪一问、哪些布局尚未核验。
7. **留意结构线索。** 观察有无变量联动、重复计算或更合适的对象表示，写明题面依据、可能的简化和待查证条件，不强凑创新点。
8. **回原题核对遗漏。** 每问都能回答“做什么、凭什么做、受什么限制、交什么成果”。

完整原题已给而输出模板暂缺时，技能仍会完成可确定的读题工作，将模板布局标为待核验。只要求读题时，它会止于任务理解，下一步只点明需要转化的关系。

默认报告 `outputs/workflow/01-read.md` 包含：整题说明、逐问任务清单、关键术语与数值、附件用途与缺口、跨问关系、有依据的结构线索、实际覆盖范围。

## 怎样连续使用

一条常用路径是：**读题与结构观察 → 选择路线 → 最小验证与真实运行 → 递进求解 → 针对性验证 → 解释与写作 → 终稿交付。** 数据核查与调研按缺口插入；新的观察可以随时引出“猜想—小检查—保留、收窄或转向”的回路，不必等待全题覆盖。

有价值的非常规方法可以直接成为首个可信参照；常规方法只在需要交付或独立核对时使用。对新表示说明它是等价、排除筛选、近似、受限方案类还是启发式。验证暂时不足时允许继续小规模探索，但不把猜想写成已证事实。分支投入由证据、潜在价值和剩余交付决定，不固定探索比例或要求所有步骤出报告。

几个容易混淆的边界：

- **第 2 步与第 6 步：** 前者定义问题是什么，后者给出能够实现的方程和条件。
- **第 5 步与第 0 步：** 前者选全题技术路线，后者决定当前该做哪项工作并调度执行。
- **第 8 步与第 11 步：** 前者快速排除基础错误，后者为重要结论补足相应证据。
- **第 9 步与第 10 步：** 前者负责各问求解，后者可在任意阶段检验结构或改进；没有传统基线也能探索，宣称数值提升时才需要同口径参照。
- **第 13 步与第 14 步：** 前者建立正文论证，后者将已支持的结论压缩为自足摘要。

已经有结果或稿件，可以直接从检查、解释或写作开始。阶段报告不是进入下一步的条件；新发现与具体错误都能触发有针对性的返回。正文可随已验证结果逐段形成，最终按“困难—观察—转化—证据—结果”重组；通用算法说明的篇幅以理解和复现需要为准。

## 它如何服务论文质量

每个技能都写明触发场景、所需材料、执行动作、实际产出和完成边界。共同约定要求先跑通真实关键路径，区分实际运行与纸面推导，并保持模型、代码、图表、正文和摘要的口径一致。

其中专门吸收了 2021—2025 年 A 题研究中的经验：评价方法先于优化搜索；检查完整行程与硬约束；可行域放宽时保留原有可行方案；区分数值收敛与物理可信；依据实际证据使用“可行解”“较优解”等表述；用主要发现组织文章，修改意见融入论证。这些是从公开材料中提炼的工作建议，不是对所有获奖论文的统计规律。

研究依据见 [近五届 A 题研究报告](../outputs/research_workflow_2021_2025/高质量数模论文的形成流程.md)。各技能采用原创组织与表述；原有第三方技能及许可继续保留。
