# 成稿与反复打磨

第5步交付真实代码、实验、图表，本步把它们组织成读者能理解和核查的论文。可直接处理用户已有稿件或局部段落，不要求七步从头执行。首次使用读 [共同约定](../math-model-skill1-read/references/principles.md)；正式排版、匿名和披露依据 [当届规则入口](../math-model-skill1-read/references/rules-and-review.md)。

## 先看文章实际能主张什么

读取原题、用户观点、已定模型、真实结果及已有稿件。抓住最能回答题目的中心发现，按“困难—观察—方法转化—证据—结果解释”形成因果主线；不强迫不同小问统一算法，也不以一个亮点代替其他必答任务。

将拟写结论与来源对应，区分已支持、部分支持、待证和被反证。稿件允许重排研究过程，不能虚构预见、实验或因果关系。缺关键结果时先成稿有依据的部分，把缺口留在工作记录或明确的草稿标记中；提交稿不保留占位，不凭空补数字。

## 在写作中检查技术逻辑

1. **问题—模型是否一致。** 检查变量含义、单位、坐标、索引、初边值、目标口径和硬约束；假设应实际简化模型且说明作用与局限。核对共用模型在后问的工况变化。
2. **模型—算法是否一致。** 关键推导、分段和判据不能以“易得”跳过；写清可复现的求解入口、参数和停止条件。核对理论保证的前提，不能由函数性质直接推出算法界，也不能把某受限类的最优解称作原问题全局最优。
3. **结果—主张是否一致。** 数值精度、物理适用性、预测表现、可行性、稳健性和最优性各用相应证据。灵敏度分析可揭示脆弱处，不预设必须得出稳健结论；没有观测数据不声称实测验证。算法性能比较检查输入、评价精度、预算及约束是否同口径。
4. **解释能否回答实际问题。** 先给各问答案，再解释主导因素、约束作用、方案权衡与适用范围。统计关联不自动写成机制，特征归因不自动写成因果；结合模型给数学、物理或决策解释，不强制使用SHAP/LIME。

影响结论的缺陷优先于润色。能由现有证据修正的直接改；需要新计算时明确最小补证任务，用户已授权求解则衔接第5步执行，否则完成独立写作并说明缺口。模型方向需要重新讨论时回到第3步，不能靠措辞掩盖。

## 围绕发现组织表达

- 标题和摘要准确表达研究对象与主要方法；摘要用问题、模型/方法、各问关键定量结果、重要证据和亮点形成自足叙述，不凑方法名和未经证实的“首次、显著、最优”。
- 正文按题目与发现自然分节，解释为什么采用这个表示、它解决哪个困难及为什么证据足够。压缩通用算法教材和重复题干，把篇幅留给本题推导、结果与验证。
- 每张图表服务一个判断，正文说明应观察什么。核对标题、轴、单位、图例、误差条、有效数字与实际数据；示意图、真实结果图、合成演练图明确身份。
- 统一符号、术语、引用和数值。来源与实际使用知识对应，长代码和全量数据移至适当支撑材料，主文保留理解关键结论必需的信息。
- 收到评价时按对结论的影响吸收，合理意见转成自然论证，错误意见给依据。修改记录与正文分开，不能让主文变成审稿问题逐项作答。结果改变时同步修改相关图表、摘要和结论。

## 导出与交付

按用户指定格式和工作稿编辑，保护用户原件。默认正文位于 `paper/`；短改写可直接交付，必要记录在 `outputs/workflow/06-refine.md`。使用现有Word/PDF/LaTeX技能按实际格式渲染核验，不能只看源文件便称版式通过；全篇声明需逐页检查最终导出，局部任务只报告局部范围。

写作持续至指定范围的主线清楚、关键数字与证据一致、技术缺陷已修复或准确界定；不为反复润色无限改写。完成时交付稿件、重要改动和会影响结论的剩余问题。需要内部质询时转第7步；最终匿名、参考文献、真实AI披露及包内容按最新规则核对，不自动上传提交。
